Written 2026-10-24 for the next agent working in this folder. Read this first, then [AGENTS.md](AGENTS.md) (rules and publishing) and [CLAUDE.md](CLAUDE.md) (UC San Diego Decorator rules).

## What this is

PARASOL is the new name for DSMLP, UC San Diego's GPU and data science computing platform. The service itself has not changed. This site is meant to be the one place for everything PARASOL, and it replaces the DSMLP documentation site (`dsmlp-docs.ucsd.edu`), which is to be decommissioned.

The site reuses the TritonAI website's design and tooling: the Decorator shell from `cdn.ucsd.edu`, the TritonAI landing-hub CSS, and the same build, validator, chrome-integrity, accessibility, language, and UX-review gates. TritonAI's source is `github.com/bpollak/tritonai-website`; compare against it when a component or check behaves unexpectedly.

## Information architecture

The site drills down from framing to tasks. `content/site.json` defines the navigation, sidebar, breadcrumbs, previous/next links, and which hero image each section uses.

1. **Home** `/` — what PARASOL is, how to reach it, where to start
2. **About** `/about/` — Why PARASOL, From DSMLP to PARASOL, How PARASOL Works
3. **Get Started** `/get-started/` — six audience guides (course students, command line, instructors and TAs, projects, researchers, labs)
4. **Documentation** `/docs/` — seven topics: Access, Workspaces & Storage, Running Jobs, GPU Access, Environments, Grading, Reference
5. **Support** `/support/` — contacts, consultations, ticket guidance

## How to work

```bash
npm ci                          # node_modules stays local; see the iCloud note below
npx playwright install chromium
npm run build && npm run dev    # http://127.0.0.1:4173/
npm test                        # the same gates CI runs
SITE_BASE_PATH=/Parasol npm run build && SITE_BASE_PATH=/Parasol npm run validate   # the Pages build
```

- **Edit pages** in `content/pages/*.md`. Ported docs pages have `format: html` and HTML bodies; edit them as HTML. Hubs (`landingHub: true`) use TritonAI hub classes (`hub-section`, `hub-action-card`, `dsmlp-*`).
- **Add a page**: create the file, add it to `content/site.json`, rebuild. The validator fails on a page no menu lists.
- **Hero art**: add or adjust a motif in `scripts/render-heroes.mjs`, run `node scripts/render-heroes.mjs <name>` (needs `cwebp`), and map a path prefix to it under `heroImages` in `content/site.json`.
- **Banners** carry an eyebrow of a word or two and the title, nothing else. Put taglines and framing in the page body; the validator fails a banner with a description under the title.
- **Home rotator**: edit slides in `content/home/hero.json`. To draw a new slide, add the motif name to `SLIDES` in `scripts/render-heroes.mjs` and re-run it. The markup, `home-hero.js`, and the validator checks are ported from the TritonAI site; keep them in step with it.
- **The validator** checks every internal link and `#fragment`, the redirect map, the old "DSMLP" name in prose, metadata, chrome integrity, and more. `VALIDATE_OFFLINE=1` skips the CDN reachability checks.

## Gotchas this session hit

1. **iCloud eviction.** This folder lives under `~/Documents`, which iCloud syncs and evicts. A read of an evicted file hangs silently: `git add` stalled for 15 minutes on one vendor template. The folder root now carries `com.apple.fileprovider.ignore#P`, so it stays local and GitHub is the backup. A fresh clone under `~/Documents` needs the same treatment; see [AGENTS.md](AGENTS.md#working-in-an-icloud-synced-checkout).
2. **Pushing.** The `gh` CLI token on this Mac lacks the `workflow` scope, so pushes over HTTPS that touch `.github/workflows/` are rejected. Push over SSH (`origin` is already `git@github.com:bpollak/Parasol.git`), with a time limit in case SSH stalls:
   ```bash
   perl -e 'alarm 90; exec @ARGV' git push origin main
   gh run watch --exit-status   # then confirm the deploy
   ```
3. **Commit identity** is set in this repository's config: Brett Pollak `<1325169+bpollak@users.noreply.github.com>`. Do not override it.
4. **Base path.** On Pages the site lives under `/Parasol` (the repository name). Anything that builds or serves `dist/` must honor `SITE_BASE_PATH`; the CI accessibility failure fixed in `16e33df` came from a test server that guessed the path from the package name.
5. **Chrome is off limits.** The header, navbar, drawer search, and footer are pinned by `config/chrome-contract.json`. A site-specific chrome change (title text, search scope, footer address) is legitimate only after a human reads the diff; then run `npm run chrome:accept`.

## Open decisions (ask Brett, do not assume)

- **Brand casing.** The site writes "PARASOL" in all caps, following the announcement draft. Changing it is a global text replacement across `content/` and `scripts/`.
- **School name.** The announcement draft uses both "Halıcıoğlu School of Data Science and Computing" and "...and Computer Science". The site uses the first. Confirm it.
- **Announcement figures.** The GPU expansion numbers (4 servers, 32 NVIDIA RTX PRO 6000 Blackwell GPUs, nearly four times peak capacity, about 66,800 and 213,000 GPU-hours) come from a draft dated 2026-10-28. They are marked `pending-announcement` in `content/facts/public-facts.json`. Brett chose to publish the review site before that date. After the release, check the final wording and figures, then change the status to `public`.
- **Production home.** `parasol.ucsd.edu` in `content/site.json` is proposed, not provisioned. Moving to Cascade or a campus host means a root-path build, the production hostname, and hosted search and analytics decisions.
- **Documentation ownership.** The ported pages came from the Datahub team's DSMLP docs (`github.com/ucsd-ets/dsmlp-docs-public`). Agree who edits them now, and re-port any DSMLP changes made after 2026-09-29 (see `scripts/port-dsmlp-docs.mjs`).
